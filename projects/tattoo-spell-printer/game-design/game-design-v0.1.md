# Playable Game Design Spec v0.1 — Tattoo Spell Printer\n\n## 1. Product Definition\n움직이는 피부에 룬을 직접 새기는 portrait mobile precision-craft game. 3–5분. 목표는 손기술 숙련감. Non-goals: 선택지 RPG, 샵 경영, 자유 그림 앱.\n## 2. Player Fantasy\n오컬트 문신사로서 움직임을 읽고 완벽한 주문을 새긴다.\n## 3. Core Player Verbs\nPlace(drag/rotate), Trace(continuous drag), Pressure(hold semantics), Repair(short retrace). 각 입력은 pose/accuracy/density/break state를 즉시 변경한다.\n## 4. Core Loop\n의뢰→배치→2–4 stroke 추적→보정→발동→결과, 세션 3건.\n## 5. Round / Session Structure\nPlacement→Inking→Correction(optional)→Activation→Result. 45–90초/case. Next/Retry.\n## 6. Game Rules\nIntegrity 3. Trace tolerance 18px. 120ms 이탈은 blemish+integrity -1. 비-junction lift는 break. Skin motion은 600ms 예고. Density >1.15 300ms는 blot. 모든 required stroke 연결+accuracy 70% 이상 성공. Break는 1회 retrace 복구 가능. 다음 case에서 case state reset.\n## 7. State Model\nPlacement는 pose, Inking은 accuracy/density/integrity/stroke, Correction은 repairs, Activation은 1.2s 판정, Result는 next/retry. Pause 시 skin motion과 timers 모두 정지. Retry는 case-local state 전부 reset.\n## 8. Interaction Spec\nStencil은 skin 내부+anchor 80% 이상 valid. Invalid confirm 불가. Rotate는 twist/handle. Trace는 ordered corridor만 ink. Lift가 cancel/segment end. Active needle이 stencil input보다 우선.\n## 9. Content Model\nCase = rune topology×stroke count×skin motion×density×forbidden zones. MVP 3 cases.\n## 10. Difficulty / Variation\n정지/완만선→교차+주기 이동→좁은 폭+밀도 구간+금지점.\n## 11. Progression\n3 case 순차 해금+best grade.\n## 12. Economy\nNot required.\n## 13. Screen Inventory\nCase Select, Tattoo Workbench, Case Result.\n## 14. Screen Flow\nSelect→Placement→Inking→Correction→Activation→Result→Next/Retry. 실패도 Result.\n## 15. Feedback System\nFit outline/snap, ink+density/needle buzz, motion warning, break/blemish error, activation success.\n## 16. Visual Direction Brief\nPortrait close-up skin work surface, readable rune and touch path, occult dark shop vs luminous ink, UI avoids covering work.\n## 17. MVP Scope\n3 clients, 3 runes, 3 motion patterns, placement/rotation, tracing/density, error/recovery, activation/result/retry. NOT IN MVP: economy/dialogue/editor/upgrades.\n## 18. Test Scenarios\n3 cases fully playable; placement understood in 2 tries; three error types distinguishable; warning permits reaction; retry resets all.\n## 19. Known Risks\nFinger occlusion, device precision variance, hold-as-pressure clarity, unfair motion.\n## 20. Wireframe Handoff\nExpress three screens, five states, valid/invalid placement, trace/break/blemish/density, motion warning/grace, correction, retry reset and transitions. No new rules required.
